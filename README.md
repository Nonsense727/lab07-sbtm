**Браузер:** Google Chrome for Testing 153.0.8010.12 (macOS 27.0.1, Apple Silicon)

## Тойм

Энэ репо нь «Уншлагын жагсаалт» вэб апп дээр хийсэн нэг 60 минутын SBTM
(session-based test management) exploratory session-ий бүрэн материал:

| Файл | Юу агуулдаг |
|---|---|
| `charter.md` | Session-ээс өмнө бичиж, commit хийсэн charter (3 аялал) |
| `session-report.md` | 60 минутын session-ий цаг тэмдэглэсэн тэмдэглэл, саадууд, цагийн задаргаа |
| `bugs/bug-01.md … bug-11.md` | 11 өөр согогийн тайлан (4 нь UI-ийн бус: BUG-02, BUG-05, BUG-08, BUG-10) |
| `evidence/` | API түвшний согогийн `curl -i` бүтэн гаралт |
| `screenshots/` | UI согогийн скриншот |

`app.js` нь багшийн өгсөн файл тул репод оруулаагүй. Ажиллуулахдаа Assignment-аас
`app.js`-ийг татаж энэ хавтаст тавина.

## Апп ажиллуулах

```bash
node app.js
# браузераар: http://localhost:3000
```

Сан суулгах шаардлагагүй. Өгөгдөл зөвхөн санах ойд хадгалагдах тул `Ctrl+C` дараад
дахин асаахад анхны 3 ном руу буцна — бүх bug report үүнээс эхэлдэг.

> Орчны тэмдэглэл: миний компьютер дээр 3000 портыг өөр нэг процесс эзэлж байсан тул
> аппыг `127.0.0.1:3000` (мөн `localhost:3000`-той ижил) дээр ажиллуулсан. `evidence/`
> доторх `curl` гаралтын URL нь үүнээс болж `127.0.0.1:3000` гэж харагдана; алхамд
> бичсэн `localhost:3000`-той ижил сервер.

## Session-ий дүгнэлт (Хэсэг E)

Хамгийн үр дүнтэй нь **Supermodel** ба **Couch Potato** хоёр аялал байв: Supermodel-оор
дэлгэц дээр шууд харагдах таван согог (BUG-01, BUG-02, BUG-07, BUG-08, BUG-11) олдсон
бол Couch Potato-гоор оролтын шалгалтгүй байдлаас үүдэлтэй дөрвөн согог (BUG-03,
BUG-04, BUG-06, BUG-09) илэрлээ. Saboteur аялал цөөн боловч хамгийн үнэ цэнэтэй
хоёрыг олсон — BUG-05 (буруу JSON-д 200 OK) ба BUG-10 (оны хязгаарлалтгүй) нь UI-аас
огт харагдахгүй, зөвхөн API-д шууд хандахад л илэрдэг. Charter-аас гадуур санамсаргүй
олдсон зүйл ч бий: бүх `<input>`-д `label` байхгүй (screen reader-т талбарын нэр
уншигдахгүй), `<meta name="viewport">` байхгүйн улмаас гар утсан дээр хуудас 980px-ээр
байрлаж жижигрэн харагдана, мөн `HEAD /` ба `OPTIONS` хүсэлтүүд 404 буцаадаг.
Шалгагдаагүй үлдсэн зүйл нь өгөгдлийн сангийн түвшин (апп зөвхөн санах ойд хадгалдаг
тул persistence, restart дараах алдагдал), хоёр хэрэглэгчийн зэрэгцээ устгах/нэмэх
үед гарч болох төлөвийн зөрчил, мөн нэвтрэлт/эрх олголт — эдгээр нь дараагийн
session-ий charter болно. Playwright автомат тестээр BUG-01, BUG-02, BUG-04, BUG-05,
BUG-08, BUG-09, BUG-10-ыг бараг шууд барих байсан (статус код, текст, тоо харьцуулах
нь энгийн assertion), харин BUG-03, BUG-06, BUG-07, BUG-11 нь зөвхөн хүний нүдээр
амархан олдоно: «мессеж буруу байна», «хүснэгт эвдэрлээ», «товч яагаад ногоон бэ»
гэдгийг автомат тестэд урьдчилан таамаглаж бичих нь бараг боломжгүй. Ерөнхийдөө
UI-ийн гоо зүй, мессежийн утга санаа, layout-ийн эвдрэл нь хүний exploratory
ажлын гол үр дүн байсан бол өгөгдлийн түвшний зөрүү (тоолуур, статус код) нь
API-ийн шууд туршилтаар л батлагдсан.

## Нэмэлт даалгавар (AI өнцөг)

Session дууссаны дараа аппын спецификацийг AI туслахад өгч «энэ аппад exploratory
тестийн charter-ууд санал болго» гэж хүссэн. AI-ийн санал миний charter-аас
чиглэлээрээ ялгаатай байв: миний charter спецификацийн 8 дүрмийг шууд шалгахад
төвлөрсөн бол AI илүү «функционал бус» тал руу түлхэж — гар утасны responsive
байдал, зөвхөн гар (keyboard-only) ашиглалт, rate limiting/нэвтрэлт, олон
хэрэглэгчийн зэрэгцээ ажиллагаа гэсэн чиглэлүүдийг санал болгосон. Үүнээс
responsive байдал ба keyboard-only хэрэглээ хоёрыг би өөрөө charter-т оруулаагүй
ч session-ийн дундуур санамсаргүй шалгасан (viewport meta байхгүй, `label` байхгүй
гэдгийг олсон) — өөрөөр хэлбэл AI-ийн санал миний олсон зүйлтэй давхцсан ч
charter-т урьдчилан тусгаагүй байсан нь миний төлөвлөлтийн сул тал байв. Харин
AI-ийн санал «аль дүрэм зөрчигдөж байна» гэдгийг тодорхой зааж өгөхгүй, ерөнхий
чиглэл өгдөг байсан тул шууд гүйцэтгэхэд тохиромжгүй. Түүхий тэмдэглэлээс bug
report бичүүлэх хоёр дахь даалгаврыг хийгээгүй — миний тэмдэглэл аль хэдийн
алхам, ажиглалт хэлбэрээр бичигдсэн байсан тул AI-ийн нэмэлт үнэ цэнэ бага
байх байсан гэж үзсэн.
